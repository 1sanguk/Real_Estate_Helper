# 사용자 변경 감사 로그

## 목적

사용자가 자신의 프로필, 관심 공고, 서류 준비 상태를 생성·수정·삭제했을 때 변경 이력을 추적한다. 애플리케이션 코드가 아니라 데이터베이스 트리거가 기록하므로 REST API 등 다른 경로에서 발생한 변경도 누락되지 않는다.

## 기록 항목

- 변경을 수행한 사용자 ID
- 변경 시각
- 대상 테이블
- 작업 종류: 생성, 수정, 삭제
- 대상 레코드를 식별하는 키
- 변경된 필드 목록
- 변경 전 값
- 변경 후 값

## 기록 대상

- `profiles`
- `saved_listings`
- `document_checks`

## 개인정보 및 보안

- 비밀번호, 인증 토큰 및 Supabase 인증 테이블은 기록하지 않는다.
- 프로필 이메일은 변경 전후 스냅샷에서 제외한다.
- 사용자는 RLS 정책을 통해 자신의 로그만 조회할 수 있다.
- 사용자는 감사 로그를 직접 생성·수정·삭제할 수 없다.
- 사용자 계정이 삭제되면 해당 사용자에게 귀속된 로그도 함께 삭제된다.

## 운영 참고

감사 로그는 개인정보의 변경 이력을 보관하므로 추후 서비스 운영 전 보존 기간과 자동 삭제 정책을 정해야 한다. 관리자 조회 기능을 추가할 때에도 최소 권한과 조회 사유 기록을 적용한다.
