# 백업 및 복구 원칙

## 보호 대상

- Supabase Auth 계정
- 사용자 프로필, 관심 공고, 서류 체크, 알림 설정
- 공식 공고 원본, 상세정보, 첨부파일 주소, 자동 분석 및 관리자 검수 결과

## 운영 원칙

- 운영 Supabase 프로젝트의 자동 백업 기능과 보존 기간을 확인한다.
- 복구 훈련은 실제 개인정보를 개발 환경으로 복사하지 않고 익명화된 별도 프로젝트에서 수행한다.
- 스키마는 `supabase/migrations`를 복구 기준으로 삼고 적용된 마이그레이션은 수정하지 않는다.
- 공고 데이터는 공식 API에서 재수집할 수 있지만 사용자 프로필과 준비 상태는 재생성할 수 없으므로 우선 보호한다.

## 장애 시 순서

1. 쓰기 작업과 자동 동기화를 중지한다.
2. Supabase 백업 시점과 장애 발생 시점을 확인한다.
3. 별도 복구 프로젝트에서 마이그레이션과 백업을 검증한다.
4. 사용자 데이터 정합성, RLS 정책, 로그인과 탈퇴를 확인한 뒤 운영을 재개한다.
5. 손실 범위와 재발 방지 조치를 기록한다.

데이터베이스 원본을 공개 GitHub Actions 아티팩트에 저장하지 않는다.
