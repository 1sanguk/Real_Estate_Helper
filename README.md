## 서비스 주소

- 웹사이트: https://1sanguk.github.io/Real_Estate_Helper/
- GitHub: https://github.com/1sanguk/Real_Estate_Helper
- 대표 로고: [`public/project-cover.png`](./public/project-cover.png)

내집레이더는 사용자의 나이, 거주 지역, 가구 구성, 소득, 자산 등 개인 조건을 바탕으로 LH·SH·HUG의 공공주택 공고를 찾고, 지원 가능성과 준비 서류를 정리해 주는 웹 서비스입니다.

## 해결하고자 한 문제

공공임대 공고는 기관마다 흩어져 있고 문서가 길어, 사용자가 자신에게 맞는 공고인지 일일이 판단하기 어렵습니다. 이 프로젝트는 공식 공고를 한곳에 모으고, 사용자 조건과 공고문을 비교해 지원 검토에 필요한 시간과 놓치는 공고를 줄이는 것을 목표로 합니다.

> 내집레이더는 LH·SH·HUG가 운영하는 공식 서비스가 아닌 개인 프로젝트입니다. 자동 판정은 신청을 돕기 위한 사전 진단이며, 최종 자격과 제출 서류는 반드시 해당 기관의 공식 공고문에서 다시 확인해야 합니다.

## 목표

- LH·SH·HUG 등 공공기관의 실제 진행 중 공고를 한곳에서 확인합니다.
- 사용자가 한 번 입력한 조건을 기준으로 지원 가능성이 있는 공고를 먼저 보여줍니다.
- 조건별 충족·미충족·확인 필요 사유를 알기 쉽게 설명합니다.
- 공고별 필수 서류와 조건부 서류를 정리합니다.
- 매일 새로운 공고를 수집하고 기존 사용자에게 다시 매칭합니다.
- 합성 공고를 사용하지 않고 공식 출처와 원문 근거를 보존합니다.

## 주요 기능

### 계정과 개인정보

- 아이디·비밀번호 회원가입 및 로그인
- 아이디와 닉네임 중복 검사
- 비밀번호 재설정 이메일
- 첫 로그인 시 필수 지원 조건 설정
- 조건 수정, 알림 설정, 회원 탈퇴
- 사용자 본인만 개인정보를 조회할 수 있는 Supabase RLS 정책
- 개인정보 변경 감사 로그와 로그인 시도 제한

### 맞춤 지원 조건

- 생년월일과 만 나이
- 거주 지역과 거주 시작일
- 가구원 수와 월평균 소득
- 총자산, 자동차 보유 여부와 차량 가액
- 무주택 여부
- 혼인·예비혼인·자녀·임신 정보
- 청약 납입 횟수
- 대학생·취업준비생 등 현재 활동 상태
- 생계·주거급여, 차상위계층, 한부모가족 정보

### 공고 탐색

- 진행 중인 실제 공고만 기본 표시
- 공고명·주소·사업 유형 검색과 지역 필터
- 지원 가능성이 있는 공고만 모아보기
- 관심 공고 저장
- 내 조건으로 지원 가능성이 있는 진행 중 공고 전체의 접수 시작일·마감일을 확인하는 월간 지원 일정 캘린더와 D-day 목록
- 검색 조건 유지와 확인한 공고 표시
- 상세 페이지에서 공식 원문, 필요 서류, 공급정보 확인
- 상세 페이지에서 자격 조건별 `충족`·`미충족`·`확인 필요` 건수와 핵심 사유 요약
- 공고 주소를 네이버 지도와 카카오맵에서 바로 열기
- 저장된 정보를 바꾸지 않고 소득·자산·가구원 수·청약 횟수 변화에 따른 판정을 비교하는 조건 시뮬레이터
- 관심 공고의 접수 기간, 공급 수, 상태 등이 바뀌면 변경 전후 내용과 이력을 표시

### 공고 분석과 운영

- 공고문에서 연령, 무주택, 소득, 자산, 자동차, 혼인 기간, 자녀, 거주 기간, 청약 납입 조건 추출
- 가구원 수별 월평균소득 금액과 사용자 소득 비교
- 신뢰도가 낮은 추출 결과는 탈락 조건으로 사용하지 않고 `확인 필요`로 표시
- 관리자 검수 페이지에서 분석 결과와 검수 상태 관리
- 동기화 실패 시 관리자 알림
- 매일 오전 10시 GitHub Actions로 공고 수집·문서 분석·사용자 매칭 재계산
- LangGraph로 변경 감지 → 영향 공고 식별 → 관심 사용자 알림 흐름을 순서대로 실행

SH에서 현재 확인된 공개 자료는 실시간 모집공고가 아니라 공급계획 데이터입니다. 실제 모집공고로 오인하지 않도록 공식 모집공고 API 또는 허용된 연계 방식이 확보되기 전까지 자동 수집 대상에서 제외합니다.

## 기술 구성

- React 19, TypeScript
- Vinext, Vite, Tailwind CSS
- Supabase Auth, PostgreSQL, Row Level Security
- 공공데이터포털 OpenAPI
- GitHub Actions (공고 동기화 배치 + GitHub Pages 배포)
- 정적 사이트(output: 'export')로 빌드해 GitHub Pages에 배포. 회원 탈퇴만 Supabase Edge Function이 처리
- ChatGPT를 활용한 기획, 구현, 오류 분석, 테스트 및 디자인 제작
- LangGraph를 활용한 정정공고 변경 감지 워크플로

코드는 거대한 클래스나 객체에 책임을 몰아넣지 않고 도메인, 기능, 인프라, 화면 단위로 분리하는 Clean Code 원칙을 따릅니다.

## AI 활용 방식 및 결과

ChatGPT를 활용해 서비스 기획, 데이터 구조 설계, React 화면 구현, Supabase 인증·보안 정책 구성, 오류 분석, 테스트 코드 작성과 사용자 경험 개선을 진행했습니다. 또한 복잡한 공공주택 공고문에서 연령·소득·자산·무주택·혼인·자녀 조건과 제출 서류를 구조화하는 규칙을 설계하고 검증하는 데 AI의 도움을 받았습니다. 실제 서비스에서는 생성형 AI가 임의로 자격을 결정하지 않고, 공식 공고에서 추출한 조건을 사용자의 정보와 규칙 기반으로 비교합니다. 근거가 부족하거나 해석이 필요한 항목은 자동 탈락시키지 않고 `확인 필요`로 안내하여 사용자가 공식 원문에서 다시 검토할 수 있도록 했습니다.

### AI가 기여한 개발 영역

- 요구사항을 기능과 데이터 모델로 구체화
- 인증, 개인정보 보호, RLS 및 감사 로그 설계 보조
- 공고 API 응답 정규화와 문서 분석 규칙 구현 보조
- 단위 테스트 작성, 오류 재현 및 원인 분석
- 화면 문구, 접근성, 반응형 UI와 브랜드 이미지 제작

AI가 생성하거나 제안한 결과는 그대로 사용하지 않고 실제 API 응답, 공식 공고문, 자동 테스트와 빌드 결과를 통해 검토했습니다.

LangGraph는 외부 LLM을 호출하는 용도가 아니라 공고 재수집 후 `변경 감지 → 영향받은 공고 식별 → 변경 이력·알림 생성` 단계를 안정적으로 관리하는 결정적 워크플로에 사용합니다. 따라서 별도의 LLM API 키나 사용자 개인정보 전송 없이 실행됩니다.

## 로컬 실행

Node.js 22.13 이상이 필요합니다.

```bash
npm install
cp .env.example .env
npm run dev
```

브라우저에서 `http://localhost:3000`으로 접속합니다.

## 환경변수

`.env.example`을 복사해 `.env`를 만들고 실제 값을 입력합니다.

```dotenv
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
SUPABASE_SERVICE_ROLE_KEY=

PUBLIC_SERVICE_KEY=
LH_ANNOUNCEMENT_API_URL=
LH_SUPPLY_API_URL=
LH_SUPPLY_DETAIL_API_URL=
HUG_LISTINGS_API_URL=
SH_ANNOUNCEMENT_API_URL=
```

`SUPABASE_SERVICE_ROLE_KEY`와 `PUBLIC_SERVICE_KEY`는 서버 전용 비밀값입니다. 브라우저 코드, 커밋, README 또는 공개 로그에 값을 노출하면 안 됩니다.

## 주요 명령어

```bash
npm run dev                 # 개발 서버
npm test                    # 자동 테스트
npm run build               # 배포 빌드
npm run sync:listings       # 공식 공고 수집
npm run analyze:documents   # 공고문 자격과 서류 분석
npm run recalculate:matches # 사용자별 지원 가능성 재계산
```

## 현재 범위와 제한

- LH 공고·공급·상세 데이터 수집이 연결되어 있습니다.
- HUG 공식 데이터 수집기가 연결되어 있으며 현재 데이터에 진행 중 공고가 없으면 화면에 표시되지 않습니다.
- SH는 실시간 모집공고 데이터가 확보되기 전까지 공식 링크만 안내합니다.
- 이메일·문자 공고 알림은 발송 사업자가 연결되지 않아 현재 서비스 내부 알림으로 제공합니다.
- 자동 추출하기 어려운 소득 비율, 우선순위, 예외 조항은 `확인 필요`로 남깁니다.
- 법적·행정적 최종 자격 판정 서비스가 아니며 공식 기관의 판단을 대신하지 않습니다.

## 개인정보와 데이터 원칙

- 합성 공고를 실제 공고처럼 표시하지 않습니다.
- 공고 출처와 공식 원문 주소를 함께 보존합니다.
- 사용자의 소득·자산·가족 정보는 본인만 조회할 수 있도록 Supabase RLS를 적용합니다.
- 비밀키는 GitHub Secrets와 로컬 환경변수로만 관리하며 저장소에 커밋하지 않습니다.
- 제출 화면과 문서에는 실제 사용자의 개인정보를 포함하지 않습니다.

## 문서

프로젝트의 데이터 원칙, 운영 방법, 백업과 검토 기록은 [`basicdata`](./basicdata) 폴더에 정리되어 있습니다.
